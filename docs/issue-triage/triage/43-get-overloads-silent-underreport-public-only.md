# TRIAGE 报告 · 条目 [43] `get_overloads` 静默少报

**裁决：值得修（🔴 高）—— 但症状成立、机制诊断错误**
**归并锚点：并入 `triage/29-…md` §6.3 单列裁决①，升级严重度并改写机制描述；不单独立计划**

## 1. 一句话结论

**症状成立，机制诊断错误。** `[43]` 记的是「静默少报 **且报的是 public 的那一个**」⇒ 隐含「工具按可见性过滤」。
**实测否证了这个推断**：查 **public** 重载时，工具把 **private** 重载返回出来了 ⇒ **`get_overloads` 完全不做可见性过滤**。
真机制就是 **triage 29 号 §3.3 早已写明的「返回同名其他重载、不含被查者」** ——
**29 号对，43 号的机制诊断错；43 号的新增价值只有一条：严重度应从 29 号的 🟡 低 升到 🔴 高。**

## 2. 核实过程（含检索范围）

**上下文**：decompilerserver，`contextAlias:"vanilla"`，MVID `61e4173561894da49d210260257b5097`（`vanilla`/`game`/`default`/`rw16` 同 MVID）。
**口径**：全部为**只读**查询，**未抢 `current`**（无 `load_assembly` / `select_context` 调用）。**未启动游戏、未调用任何改状态的 MCP 工具。**

板上 [43] 自己只查了 **private** 那一个（`06006323:M`），看到「只返回 public 的那个」，于是推断出「按可见性过滤」。
**这是从一个方向的观测推断机制**（AGENT-BRIEF §3.8 ②）。**决定性实验是反过来查 public 的那个：**

| # | 调用（均带 `contextAlias:"vanilla"`） | 返回 |
|:--:|---|---|
| 1 | `get_member_details("…:06006323:M")` | `Void RecalculatePerceivedPathCostAt(IntVec3 c)`，**`accessibility: Private`** |
| 2 | `get_member_details("…:06006324:M")`（经 #3 返回体） | `Void RecalculatePerceivedPathCostAt(IntVec3 c, Boolean& haveNotified)`，**`accessibility: Public`** |
| 3 | `get_overloads("…:06006323:M")`（查 **private**） | `totalEstimate: 1` = **仅** `06006324:M`（Public）。**与板上读数逐字一致** |
| 4 | `search_members(query="RecalculatePerceivedPathCostAt", declaringTypeFilter="Verse.AI.PathGrid")` | `totalEstimate: 2`：`06006323:M` + `06006324:M`。**与板上读数逐字一致** |
| 5 | 🚩 **`get_overloads("…:06006324:M")`（查 public —— 决定性）** | `totalEstimate: 1` = **仅 `06006323:M`，且返回体里 `accessibility: "Private"`** |
| 6 | `get_overloads("…:06003A6B:M")`（`Verse.ThingOwner.Contains(ThingDef)`，**第二个类型**） | `totalEstimate: 2` = `06003A5A` `Contains(Thing)` + `06003A6C` `Contains(ThingDef, Int32)`，**不含被查者** |

**读法**：#5 是本报告的全部要害。
- 若存在可见性过滤（板上假设），查 public 重载应当返回 **0** 条（其余全是 private）或 **1** 条（它自己）。
- 实测返回 **1 条，且是 private 的那个** ⇒ **过滤不存在**。

⇒ **真机制：`get_overloads(N)` 返回与 `N` 同名的全部其他重载，不含 `N` 自己，可见性一律不管。**
⇒ 在 `Verse.AI.PathGrid` 这个例子里，重载总数是 **2**，工具返回 **1**，**这个 1 在其自身语义下是正确的**，不是「少报」。

### 2.1 为什么 29 号的观测无法区分这几种假设（这解释了 43 号为什么会误诊）

29 号实测的是 `Verse.ThingOwner.Contains`：`Contains(Thing)` / `Contains(ThingDef)` / `Contains(ThingDef, Int32)` **三个全是 public**，
查 `06003A5A` 得 2 条。在「3 个全 public」这个格子上，下面四种机制**预测完全相同**，29 号的观测对它们**零判别力**：

| 假设 | 查 public 的成员，预期返回 |
|---|---|
| H1「不含被查者，其余全给」 | 2 条（另两个 public） |
| H2「只给 public，且不含被查者」 | 2 条 |
| H3「只给 public，含被查者」 | 3 条 ❌ 排除 |
| H4「只给 public」 | 3 条 ❌ 排除 |

⇒ 29 号无法区分 H1 / H2，**它选了 H1（正确）但当时并没有证据支持它**。
`Verse.AI.PathGrid` 之所以有判别力，正是因为它的 2 个重载**一个 private 一个 public** ——
**#5 这一次调用就把 H2 排除掉了。** 这条方法论本身值得记：*当候选机制的预测在某组样本上完全重合时，需要换一个能分开它们的样本，而不是在重合的样本上投票。*

## 4. 影响与严重度复评

- **真实性**：✅ 板上读数（`totalEstimate: 1` vs `2`、两条 memberId、`Private`/`Public`）**逐字复现**；❌ 但机制归因错误。
- **严重度：🟡 低 → 🔴 高（复评上调）**。按 AGENT-BRIEF §5.2 尺子：
  - 🔴「会让自动化得出**事实相反**的结论」—— **命中**。`totalEstimate: 1` + `hasMore: false` 的返回形状，在字面上就是「这个方法只有 1 个重载」。
    谁拿它论证「不存在重载歧义」，就会拿到**假阴性**；而按板上 `D-W8-05` 的原话，这个假阴性**恰好否认的正是「补丁挂错重载」那个 bug** ——
    **错误的结论恰好掩护了最贵的那个 bug**，这是最坏的组合。
  - 且该假阴性**不可自纠正**：`hasMore:false` 是一个**主动的谎**，不是沉默的省略。
- **是否设计使然**：**部分是**。「返回同名其他重载」可以是一种合理语义；**但用 `totalEstimate` 承载它就不合理** ——
  `totalEstimate` 在其它工具里一律表示「全量计数」，在这里却表示「全量减一」。
  ⇒ **病不在语义，在语义与字段名的错配。**
- **可修性**：**本项目侧修不了**（`decompilerserver` 源码不在本仓库，见 §5）。本项目侧只能写进规范。

**我的判断：这类条目不该进索引 —— 更准确地说，该进的是「待核实」，不是「已记录」。**

理由三条：

1. **索引行是全板唯一的速查面，而它现在承载了未经核实的断言。**
   本流水线的全部价值建立在「`file:line` 引用逐字可核」上；把**正文缺失**的条目按正常格式写进索引，
   等于让「有索引行」这件事本身**替代了「有出处」**——这正是 §3.7 第 1 条「转抄别人的表会连错误一起抄，且错误因转抄而更可信」。

2. **它把「我不知道」记成了「我查过，没找到」，两者在索引层不可区分。**
   后者是一个**已完成的检索**（可复用），前者是一个**未完成的检索**（须重做）。
   但索引行里**没有任何字段**能让读的人区分这两种状态 ⇒ 该字段缺失。

3. **它已经产生了一次实际损害** —— 本次派单就不得不为 [42]/[44] 单独开一节「不要 triage」，
   而这条指令的存在本身会**诱发下游跳过真正的核实**（下次同类条目可能被当成「又一条空壳」而略过）。

**建议（按成本从低到高）**：

| 优先级 | 做法 | 成本 |
|:--:|---|---|
| 1 | 索引表**增加一列「出处」**，取值 `已核` / `正文缺失·待核实`；[42]/[44] 标后者 | 改索引表格式 |

**在三者之间，默认选 1**：它最小侵入，且能立刻让「可核实 / 不可核实」在速查层可见。
